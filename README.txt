AFFGOLD — краткое руководство
=============================

БЫСТРЫЙ СТАРТ БЕЗ ПРАВКИ КОДА

1. Дважды нажмите open-editor.bat.
2. Откроется http://127.0.0.1:4177/admin/.
3. Добавьте проект или нажмите «Дублировать» у похожего проекта.
4. Заполните тексты, оценки, цвета, логотип, ссылку и источники. Новый проект
   создаётся как черновик и не виден посетителям.
5. После проверки условий укажите дату «Факты проверены», ответственного
   редактора, выберите статус «Опубликован» и нажмите «Сохранить и пересобрать».
6. После работы вернитесь в окно редактора и нажмите Ctrl+C, чтобы остановить его.

Редактор проверит данные, сохранит базу, создаст обзор, карточки, цветовую
тему, подборки и sitemap. Если сборка или проверка не пройдёт, исходная база
и загруженные логотипы будут восстановлены автоматически.


ГДЕ ХРАНИТСЯ КОНТЕНТ

Единый источник данных проектов: js/projects-data.js

Через админку редактируются:
- название, id и адрес обзора;
- описание, особенности и три подробных текстовых блока обзора;
- бонус, вейджер, сроки выплат, промокод и внешняя ссылка;
- пять оценок рейтинга;
- основной/дополнительный цвета и градиент кнопки;
- платёжные методы, метки и типы бонусов;
- статус публикации, даты изменения/проверки и окончания оффера;
- оператор, лицензия, юрисдикции, ответственный редактор и источники;
- старые адреса для редиректов и краткий журнал изменений;
- локальный логотип PNG, JPEG или WebP до 128 КБ.

Карта текстов:
- content/site.json — название и описание сайта, SEO-метаданные главной и каталога,
  подписи редакции, партнёрские предупреждения и ссылки ответственной игры;
- content/seo-pages.json — тексты рейтингов, бонусов, гайдов, платёжных и
  редакционных страниц;
- js/projects-data.js — тексты и факты конкретных проектов (лучше менять через
  локальную админку);
- index.html и catalog.html — только уникальные видимые блоки главной и каталога,
  которые не относятся к карточкам.

Не меняйте содержимое между комментариями AFFGOLD:*:START и AFFGOLD:*:END:
карточки туда подставляет генератор. scripts/build-seo.mjs содержит шаблоны и
логику сборки, а не основной редакционный текст. После изменения JSON или HTML
обязательно запустите npm run build.


СТАТУСЫ И SEO-БЕЗОПАСНОСТЬ

- «Черновик» хранится в базе, но не создаёт публичную карточку и страницу.
- «Опубликован» попадает в карточки, обзор, sitemap и подборки.
- «Архив» сохраняет историю проекта, но убирает его из публичной выдачи.
- Старые записи без поля status считаются опубликованными. Это сделано для
  совместимости с существующей базой.
- Опубликованный ID заблокирован от изменения. Если нужен новый проект,
  нажмите «Дублировать»: копия всегда создаётся черновиком.
- При смене адреса опубликованного обзора редактор запросит подтверждение и
  добавит прежний путь в «Старые адреса для редиректов». Сервер также проверяет,
  что этот путь не потерян.
- Кнопка удаления у опубликованного проекта переводит его в архив. Физически
  удалить можно только неопубликованный черновик.

Даты имеют разный смысл:
- «Текст изменён» обновляется автоматически при изменении содержания;
- «Факты проверены» меняется только вручную после проверки условий;
- смена цветов не обновляет ни дату текста, ни дату фактической проверки;
- «Впервые опубликован» ставится один раз при первой публикации;
- «Оффер действует до» можно оставить пустым.

Перед первой публикацией обязательны ответственный редактор, дата проверки и
хотя бы один источник с датой. Источники заполняются по одному в строке:
  Официальные условия | https://example.com/terms | 2026-08-21

Итоговый рейтинг не вводится вручную. Это среднее арифметическое пяти оценок
с одинаковым весом 20%, округлённое до одного знака.


ИСХОДНИКИ И СГЕНЕРИРОВАННЫЕ ФАЙЛЫ

Редактировать вручную:
- js/projects-data.js — база проектов (предпочтительно через админку);
- content/site.json — общие подписи, предупреждения и метаданные;
- content/seo-pages.json — тексты информационных и редакционных страниц;
- index.html и catalog.html — исходная разметка уникальных блоков вне managed-секций;
- css/base.css — переменные, базовые элементы и шапка;
- css/components.css — общие компоненты и reveal;
- css/home.css — главная;
- css/catalog.css — каталог и фильтры;
- css/review.css — обзоры;
- css/seo.css — статьи, рейтинги и подборки;
- css/responsive.css — общая адаптивность;
- css/project-themes.css — общая логика фирменных тем;
- css/motion.css — анимации и reduced motion;
- js/main.js — общая навигация, промокоды и reveal;
- js/catalog.js — select, фильтры, сортировка и мобильная панель каталога;
- js/admin.js — интерфейс редактора.

Не редактировать вручную — они пересоздаются:
- reviews/, ratings/, bonuses/, payments/, guides/, about/ и другие SEO-разделы;
- css/project-theme-tokens.css;
- css/site.css и css/*-page.css;
- review.html, robots.txt и sitemap.xml;
- SEO-метаданные и карточки внутри managed-блоков index.html и catalog.html.

Карточки главной и каталога уже находятся в HTML. JavaScript только фильтрует
готовые элементы, поэтому страницы не прыгают при загрузке и остаются
понятными поисковикам без выполнения JS.


КОМАНДЫ

Для сборки используется Node.js 22 (версия закреплена в .nvmrc и
.node-version; допустимый диапазон также указан в package.json).

Полная пересборка:
  npm run build

Проверка данных, ссылок, id, тем и бюджетов изображений:
  npm run check

Только сборка CSS-бандлов:
  npm run build:css

Полный релиз: сборка, проверки, публичный каталог и воспроизводимый ZIP:
  npm run release

Повторная проверка готового каталога и ZIP:
  npm run smoke

После загрузки на production:
  npm run smoke:live

Повторное создание оптимизированных баннеров и JoyCasino logo (нужен ffmpeg):
  node scripts/optimize-assets.mjs

На Windows полную сборку и проверку также запускает rebuild-site.bat.

Готовый ZIP для загрузки на Beget создаёт build-beget.bat.


КАК УСТРОЕНА СБОРКА

scripts/lib/projects.mjs
  Читает и строго проверяет базу, формирует JS и CSS-токены тем.

scripts/build-css.mjs
  Собирает читаемые CSS-модули в отдельные лёгкие бандлы для home, catalog,
  review и SEO-страниц. site.css остаётся полным бандлом для админки.

scripts/build-seo.mjs
  Сначала строит весь результат во временной папке. Только после успешного
  рендера делает резервную копию и заменяет готовые страницы. При ошибке
  возвращает предыдущую рабочую версию.

scripts/check-site.mjs
  Проверяет итоговый сайт перед публикацией. Ошибка даёт ненулевой exit code.

scripts/build-beget.mjs
  Копирует только публичную часть сайта в beget-upload и повторно проверяет
  комплект. Локальная admin/, js/admin.js и js/projects-data.js на хостинг
  не попадают; из CSS копируются только четыре используемых page-бандла.
  В reviews/ копируются только проекты со статусом published; draft и
  archived не могут попасть в ZIP из-за старого HTML. Релизный .htaccess
  дополнительно возвращает 404 для их старых review/query-путей, поэтому
  забытая на хостинге папка не сделает проект публичным повторно.

  redirectAliases опубликованных проектов превращаются в настоящие 301 в
  релизной копии .htaccess. Небезопасный, повторяющийся или занятый URL
  останавливает сборку вместо создания конфликтующего редиректа. Там же
  автоматически создаются 301 для review.html?project=<id-or-slug>;
  неизвестное значение остаётся на noindex-странице review.html. Шесть старых
  индексированных *-casino.html также направляются сразу на текущий slug, даже
  если адрес обзора позднее изменится.

scripts/create-release-zip.mjs
  Создаёт affgold-beget.zip без PowerShell и внешних зависимостей. Пути внутри
  архива всегда используют «/», файлы отсортированы, время нормализовано.
  После записи проверяются CRC32, состав и совпадение каждого файла с
  beget-upload.

scripts/check-release.mjs
  Проверяет публичный состав, отсутствие служебных файлов, локальные ссылки,
  .htaccess, структуру ZIP и побайтовую воспроизводимость повторной упаковки.
  release-manifest.json содержит SHA-256 Build ID всего публичного комплекта.

scripts/smoke-live.mjs
  После публикации сначала сравнивает production Build ID с локальным, затем
  проверяет страницы, статику, приватность служебных файлов, 404, заголовки
  и все 301.

scripts/admin-server.mjs
  Работает только на 127.0.0.1, не отдаёт .git/scripts, ограничивает размер
  запросов, проверяет свежесть базы и объединяет сохранение, сборку и проверку
  в одну транзакцию.


ПУБЛИКАЦИЯ НА BEGET

1. Сделайте резервную копию текущего корня домена и его серверных правил.
2. Запустите build-beget.bat (или npm run release).
3. Полученный affgold-beget.zip загрузите в корневую директорию домена,
   указанную в разделе «Сайты» панели Beget.
4. Распакуйте архив с заменой файлов. В корне домена должны лежать именно
   .htaccess, index.html, css/, assets/, js/ и reviews/, а не папка
   beget-upload целиком. Убедитесь, что скрытый файл .htaccess извлечён.
5. Удалите старые файлы, которых нет в beget-upload, только после резервной
   копии. В частности, старые *-casino.html не должны продолжать отдаваться
   как страницы: их 301 уже описаны в .htaccess.
6. Запустите npm run smoke:live. Команда проверит актуальную версию, CSS,
   логотип, custom 404, security/cache headers, старые URL и сохранённый
   affiliate-редирект /velora.
7. Дополнительно проверьте в браузере прямые адреса:
   https://affgoldprod.com/css/home-page.css
   https://affgoldprod.com/assets/images/velora-logo.svg
   https://affgoldprod.com/catalog.html

HTML использует относительные внутренние ссылки и удобен для локального
предпросмотра. Production .htaccess и canonical рассчитаны на корень
affgoldprod.com; готовый Beget-комплект нельзя распаковывать в подпапку.

По умолчанию canonical и sitemap собираются для https://affgoldprod.com.
AFFGOLD_SITE_URL меняет canonical генератора, но для переноса на другой домен
также нужно осознанно заменить production origin в .htaccess,
scripts/lib/release-redirects.mjs и smoke-live.mjs. Текущий релизный профиль
намеренно не позволяет случайно опубликовать affgoldprod.com как другой сайт.

Админка является только локальным инструментом и намеренно не публикуется.
Для редактирования и пересборки используйте open-editor.bat на рабочем
компьютере, затем создайте новый проверенный релизный ZIP.


ПРАВИЛА СКОРОСТИ

- Не вставляйте изображения как data URL в projects-data.js.
- Загружайте логотипы через локальную админку; лимит — 128 КБ.
- Не возвращайте banner-velora.png или joy-logo.svg в публичную разметку:
  используются компактные AVIF/WebP версии.
- После изменения изображений всегда запускайте check-site.mjs: в нём
  закреплены бюджеты веса.
- Не подключайте css/styles.css на публичные страницы: посетителю должны
  отдаваться готовые *-page.css без цепочки @import.


ВОССТАНОВЛЕНИЕ

Все удалённые устаревшие файлы и любые предыдущие версии доступны через Git.
Если локальный редактор сообщает, что база изменилась, обновите страницу — это
защита от перезаписи более свежих данных старым черновиком.
